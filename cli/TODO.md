## 1. CLI и безопасная генерация

- [ ] **Режим проверки без записи (`--check` / `--dry-run`):** валидировать
  `compile.yaml`, ничего не создавать и возвращать корректный exit code.
- [ ] **JSON-формат ошибок (`--format=json`):** выводить структурированный
  список ошибок с полями `path` и `message`.
- [ ] **Политика существующих файлов:** по умолчанию пропускать существующие
  файлы с сообщением `Skipping <file> (already exists, use --force to overwrite)`.
- [ ] **Флаг `--force` / `-f`:** явно разрешать перезапись существующих файлов.
- [ ] **Generated header:** добавлять в каждый созданный YAML-файл заголовок:
  `# Generated by DevInit. DO NOT EDIT DIRECTLY. Source: compile.yaml`.
- [ ] **Drift detection:** предупреждать, если ранее созданный файл был изменён
  вручную; определить способ хранения контрольной суммы и поведение при конфликте.

## 2. Модель Compose и локальная разработка

- [ ] **Поле `build`:** добавить `build: string | null` в спецификацию сервиса и
  передавать его в `docker-compose.yaml`.
- [ ] **Поиск Dockerfile:** если `build` не указан, искать Dockerfile в корне и
  разрешённых подпапках; проверять существование явно указанного пути.
- [ ] **Проверка Compose-портов:** валидировать host/container port, диапазоны,
  протокол и коллизии host ports между сервисами.
- [ ] **Database volumes:** для PostgreSQL, MySQL, MariaDB и MongoDB добавлять
  именованные volumes с корректными mount paths.
- [ ] **Database healthchecks:** генерировать healthcheck для встроенных БД и
  использовать `depends_on.<service>.condition: service_healthy` там, где
  сервис зависит от БД.
- [ ] **`.env.example`:** создавать шаблон переменных с пустыми плейсхолдерами.
- [ ] **Локальный `.env`:** генерировать только для локального режима, не
  перезаписывать существующие переменные и не выводить секреты в консоль.
- [ ] **Compose interpolation:** заменять генерируемые пароли на ссылки вида
  `${POSTGRES_PASSWORD}` вместо открытых значений.
- [ ] **`.gitignore`:** добавлять `.env` только при отсутствии этой записи.
- [ ] **Безопасность секретов:** определить правила имён переменных, генерации
  паролей и запрет публикации `.env` в Git.

## 3. Kubernetes stack

- [ ] **Compose -> Kubernetes environment:** сопоставлять сервис и контейнер,
  преобразовывать `KEY=VALUE` в `{ name, value }`, корректно обрабатывать
  пустые значения и `${KEY}`.
- [ ] **Kubernetes Service:** генерировать `k8s/<workload>-service.yaml` для
  Deployment с портами; использовать `ClusterIP` по умолчанию.
- [ ] **Selector consistency:** связывать Service с labels Pod и валидировать,
  что selector действительно выбирает Pod.
- [ ] **Service port mapping:** определить и валидировать соответствие
  Compose host/container ports и Kubernetes `port`/`targetPort`.
- [ ] **Probes:** поддержать пользовательские `livenessProbe` и
  `readinessProbe` для HTTP GET и TCP; не подставлять silent defaults без
  явной настройки пользователя.
- [ ] **Resources:** валидировать `requests` и `limits`, включая допустимые
  ключи и единицы CPU/памяти (`m`, `Mi`, `Gi` и необходимые Kubernetes units).
- [ ] **Secret/ConfigMap injection:** поддержать `envFrom.secretRef` и
  `envFrom.configMapRef` с проверкой взаимоисключающих полей.
- [ ] **Raw overrides / deep merge:** разрешить произвольные поля Kubernetes
  (`tolerations`, `securityContext`, `affinity` и другие) с определённым
  правилом конфликта между typed-полями и overrides.
- [ ] **Offline Kubernetes schema validation:** добавить опциональную проверку
  сгенерированных манифестов по официальной OpenAPI/JSON-схеме.
